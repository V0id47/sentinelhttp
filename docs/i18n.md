# Localization contract

SentinelHTTP supports English (`en`), Spanish (`es`), Russian (`ru`) and
Simplified Chinese (`zh-CN`) for human-facing CLI help, errors, terminal,
Markdown and HTML reports, and the local dashboard. Pass `--lang` to a CLI
command; the dashboard detects the browser locale and provides a selector that
persists only in browser local storage. Unsupported locales fall back to English.

JSON reports remain language-neutral and byte-stable for interchange and diff.
They retain English source catalog prose for schema compatibility. Presentation
uses a fixed, versioned catalog: finding prose is translated only when the rule
ID, rule version, source narrative and limitations match the shipped catalog.
Changed or unknown prose stays verbatim with a visible fallback warning.
Known fixed report limitations are translated by exact match. Evidence,
protocol names, rule IDs, status codes, URLs, hostnames and raw JSON are never
translated. Dates in human views use the selected locale.

The TypeScript catalog is in `frontend/src/i18n.ts`; the Vite build exports its
fixed translations to `internal/core/localization/catalog.json`. The finding
source catalog is generated from Go by `go run ./tools/cataloggen` and checked
against the Go rule catalog in tests. Run `npm run build` in `frontend` after
changing translations, then the Go test suite. `artifacts/phase18/audit-catalog.mjs`
checks coverage of shipped finding phrases.
